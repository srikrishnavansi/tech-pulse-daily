Newest tools

model launch

Qwen3.8-Flash-Next

Alibaba's preview of the Qwen4 architecture: a 125B-parameter MoE model with only 6B active per token, plus 51B N-gram embedding parameters (180B on disk), native 262K context extensible to 1M. Shipped with Unsloth GGUF quants (v0.1.804-beta) so it runs today via llama.cpp or MLX-Serve.

First-week reports (see X above) already show it running on a single 24GB GPU and on Apple Silicon at usable decode speeds — worth a look for any local-fallback story alongside RealGenie's cloud agents.

show hn

kelviq/tare

Reads Claude Code's own local session logs and answers plain-English questions about where your usage went — token audit, limit diagnosis, usage forensics. Nothing leaves the machine.

A straight answer to 'why did my quota vanish' without hand-grepping JSONL logs.

show hn

issacnitin/RealDiff

Diffs a pull request's actual runtime behavior across six languages, not just its text. Redacts credential-shaped values (JWTs, AWS keys) on display while still hashing the real value, so two different secrets still register as a divergence.

Exactly the kind of verification tooling the 1800-PR story above runs on — worth trying against agent-authored PRs before merge, not just human ones.

A real transformer decoder layer, in RTL, on FPGA

Runs one decoder layer of Qwen2.5-0.5B on FPGA, bit-exact against a NumPy reference model, with every silicon value verified. Measured 0.56 tok/s — a proof of correctness, not speed.
