Repo of the day

460 ★

tigerless-labs/agent-memory

Local-first, agent-agnostic long-term memory runtime. Memories are plain markdown files — the single source of truth — with a SQLite index beside them that's a disposable cache, not a database of record. No LLM client inside the library and no keys to install; judgment for what to write is borrowed from the host agent's own CLI. Three read tracks: deterministic MEMORY.md injection at session start, BM25 recall with progressive disclosure, and the plain directory tree reachable with ls and grep. All nine writer/reader pairs across Claude Code, Codex CLI and Hermes are tested to round-trip specifics intact.

Why it matters: This is close to the memory layer worth sketching for the harness — markdown-as-source-of-truth means you can read and hand-edit memory without a special tool, and a disposable index means a bad rebuild never corrupts history. The cross-host read/write testing (Claude Code writes, Codex CLI reads, and back) is the part worth stealing if RealGenie's agents ever need to share memory across different harnesses.

Newest tools

launch

timgordontg/engrim

Local-first, project-scoped SQLite memory engine aimed at AI coding CLIs — Claude Code, Cursor, Windsurf, Google Antigravity. Curates roughly 4,000 characters of episodic working memory per project, backed by FTS5 lexical search plus vector cosine search in a single ~/.engrim/memory.db, with a provenance layer that tracks which model wrote which memory.

A second, independently-built answer to the same problem agent-memory is solving, launched the same week. Worth reading both before building anything in-house — the provenance tracking (which model wrote what) matters the moment more than one model touches the same project memory.

A CLI-plus-skills pattern for turning chat logs into daily briefs

Local-first system that mines WeChat exports through a read-only CLI built entirely on Codex skills: searchable chat history, daily briefings, follow-up and opportunity tracking, no cloud calls.

The WeChat part doesn't apply here, but the shape does — a read-only CLI plus a stack of narrow skills producing a daily brief is the same pattern this digest tool runs on. Worth a skim for how they drew the skill boundaries.

vLLM's speculative decoding guide adds AMD-specific drafting methods

Practical writeup benchmarking five speculative-drafting approaches — native MTP, Gemma 3 MTP, EAGLE-3, DFlash, DSpark — on MI300X and MI355X via ROCm, with throughput numbers and tuning guidance for each.

The reference doc if any self-hosted inference work moves onto AMD hardware. The tuning knobs (which drafter for which model shape) matter more than the topline numbers, which are vLLM's own benchmarks.
