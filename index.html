2,036 ★ new this week, breakout list

jaredpalmer/kev

Trainable family of decision models (0.8B/4B/9B) built on Qwen3.5, following the interface of TypeSafe AI's proprietary Jev: feed it a document plus typed yes/no, multiple-choice, or ordered-score questions and it returns calibrated probabilities in a single forward pass — no generation, no LLM call. Palmer ported it to Qwen3.5 for about $95 in H100 time; the 9B variant trails the closed Jev by roughly 4.5 points on TypeSafe's own dev set, weights and training code included.

Why it matters: If any of RealGenie's 13 agents burn a full Claude call on what's really a yes/no or multiple-choice decision — routing, triage, a guardrail check — this is the shape of what replaces it, and it's now cheap enough to train and host yourselves instead of paying an API per decision.

Newest tools

launch

Jevals

Evals and guardrails for agent traces built on Jev/Kev/Laya-style decision models instead of an LLM judge: 37 built-in checks, YAML config, adapters for the OpenAI Agents SDK, LangGraph and the Claude Agent SDK, plus an MCP server and CLI. A whole trace's checks go out as one request rather than one LLM call per assertion.

This is a drop-in way to cut eval cost on RealGenie/ReBuddy traces — plain code still handles the mechanical checks (tool-call matching, secret regexes), and only the judgment calls hit a decision model instead of an LLM judge.

launch

Splash

Local inference engine for Apple silicon that serves models to coding agents over OpenAI- and Anthropic-compatible endpoints (chat completions, responses, and Messages APIs, with streaming, tool calls, JSON Schema output) from one Mac. Apache-2.0, `brew install incoai/tap/splash`. On a 48GB M5 Pro it's reported to decode Qwen3.8-27B at 2x the next-fastest engine with a 282ms first token at 32K cached context.

A real local harness for agent dev and testing that speaks the same API shape you already build against, without burning API credits per iteration.

Why MCP Was Always a Bad Idea

Argues MCP is already legacy weight — capable coding agents can just read API docs and hit HTTP endpoints or CLIs directly, so the extra protocol layer (schemas, servers, discovery) is overhead most integrations don't need.

You maintain MCP servers for this team's tools — worth reading before standing up the next one; the counterargument is weaker for high-churn public tools than for internal, stable ones, but it's a real challenge to the default.

Claude Code v2.1.278: auto mode overhead no longer billed

Auto mode's classifier now defaults to running server-side for API, Enterprise, Bedrock, Vertex, Foundry and gateway users, so the classification step itself isn't charged. /status gained a row showing whether a session's classifier ran server-side.

Direct cost line item if the team leans on auto mode in day-to-day Claude Code sessions.

213 pts · Show HN

Mini-AGI: continual learning from scratch on 8GB VRAM

Byte-level model that assembles its own architecture, trains from a single stream of data on one consumer GPU, and grows or prunes capacity on the fly instead of catastrophically forgetting as new data arrives. Weights are paged from disk, so scale is bounded by disk space, not VRAM. The author is explicit it's toy-level, not frontier capability.

A different angle on 'self-improving' than fine-tuning or RAG — worth a skim if you're thinking about how agents should pick up new property-specific knowledge over time without a retrain cycle.

33 pts · Show HN

Lossless-memory: a personal AI memory that never summarizes

Keeps every line of a conversation, timestamped, treating any compact or summarized view as an index over the raw log rather than a replacement for it — the opposite bet from most agent-memory systems that compact aggressively to save context.

Directly relevant if you're designing the memory layer for these agents — a concrete argument for keeping raw logs authoritative and only summarizing for retrieval, never for storage.
