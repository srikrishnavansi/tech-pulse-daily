Newest tools

show hn launch

Copperhead

Takes a natural-language brief and runs the full hardware pipeline: spec, architecture, part selection, schematic, first-draft layout, gerbers, firmware scaffold, dev plan. Reads and edits real KiCad schematic/PCB files, keeps markdown design docs as its memory across sessions, and verifies its own work by running KiCad ERC/DRC checks before handing back a result. Installs via npm, drives through Claude Code or Cursor.

Same agent pattern we reach for on RealGenie — plain-file memory instead of a vector store, a self-check loop instead of trusting the first pass — just pointed at hardware instead of property workflows. Worth reading the memory design even if nobody here touches a PCB.

platform launch

Applied Compute AC2

Hosted platform for training and serving open-weight models: pick a base model, bring your own training harness (a few dozen lines to start), serve it, and feed production traces back in via on-policy self-distillation for the next run. Setup is agent-first — point a coding agent at platform.appliedcompute.com/agents.md and it installs the CLI, logs in, and wires up an MCP server for you.

The self-distillation loop — production traces becoming the next model's training signal — is the exact shape of the memory/self-improvement problem we keep circling for RealGenie's agents. Worth reading for the eval design even without migrating onto it; it's a hosted product, not open source, so the usual lock-in questions apply.

50 pts · HN

Qwen3.8-27B quantized down to 1-bit, benchmarked honestly

Quesma ran GPQA Diamond, IFBench and Terminal-Bench 2.1 against the full BF16 model, then again at each quantization step. Q4_K_M (17GB) tracks the full-precision scores closely across all three benchmarks; accuracy collapses toward random chance at 1-bit.

If a self-hosted fallback model is ever on the table, this is an actual accuracy-vs-size curve instead of a vendor claim — 4-bit is the floor worth trusting, 1-bit isn't.

HuggingFace · Multiverse Computing

Refusal is a slope, not a boundary — and tightening it leaks

Multiverse Computing's boundary-aware self-distillation work shows a model's refusal probability shifts gradually across a topic rather than switching cleanly. Training a model to refuse more of the harmful side of a boundary measurably spills over into refusing legitimate adjacent prompts. Released an eval dataset (MultiverseComputingCAI/llm-refusal-evaluation) alongside the writeup.

Directly relevant to guardrail tuning on RealGenie/ReBuddy agents — over-refusing legitimate tenant or maintenance questions in the name of safety turns out to be a measurable failure mode, not just an anecdotal one.

git.kernel.org

AI crawlers are now ~98% of git.kernel.org's traffic

Konstantin Ryabitsev's numbers: roughly 6M requests a day demanding random commits, two-thirds caught by the Anubis challenge but a third still getting through, legitimate traffic down to about 2% of the total, and 14 CPU cores across kernel.org's nodes doing nothing but rendering commit pages for scrapers.

A concrete data point for anyone estimating what unthrottled scraping does to public-facing infra — worth remembering before exposing docs, changelogs, or a repo mirror without rate limiting.
